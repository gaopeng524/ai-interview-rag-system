# 12 · 踩坑记录与排查思路

> 这一篇是整个项目**实战价值最高**的一篇——下面每个坑都是真实踩过的，附症状、原因、修复、以及"再遇到怎么查"。踩坑不可怕，会排查才值钱。

## 坑 1：数据库密码是明文，登录一直失败

**症状**：`alice` / `123456` 登录返回"用户名或密码错误"。

**排查**：直接查库发现 `users` 表里 `alice`、`test` 的 password 是**明文 `123456`**，而 `bob` 是 `$2a$10$...` 开头的 BCrypt 哈希。

**原因**：`alice`、`test` 是早期用原生 SQL 手工插入的（`INSERT INTO users ... VALUES ('alice','123456')`），没走 `UserService.createUser`，也就没被 `BCryptPasswordEncoder.encode` 处理。而 `BCryptPasswordEncoder.matches("123456", "123456")` 会把第二个参数当**哈希去解析**——明文没有 `$2a$` 结构，直接解析失败返回 false。**所以"密码看起来没错，就是登不上"。**

**修复**：用 Python bcrypt 生成 `123456` 的正确哈希，`UPDATE users SET password='<hash>' WHERE username='alice'`。

**教训**：**永远走代码注册，别手插 SQL。** 看到 `$2a$10$` 开头的密码是哈希，看到普通字符串就要警惕——那是没加密的明文。

## 坑 2：SSE 流式被 Spring Security 拒绝（最隐蔽的一个）

**症状**：网页流式对话出现 **network error**；服务端日志：
```
AuthorizationDeniedException: Access Denied
... Unable to handle the Spring Security Exception because the response is already committed
```

**排查**：第一次看到完全懵——明明登录了，接口也是 `authenticated()`。后来意识到：**SSE 流式请求是异步的**。Spring MVC 处理流式请求时，主线程返回后要**异步派发（async dispatch）**再继续推送。而这个异步派发会**重新走一遍安全过滤器链**。

**原因**：Spring Security 默认 `requireExplicitSave = true`，即 SecurityContext 需要显式保存到 `SecurityContextHolder`。异步派发时上下文没保存 → 派发线程看到的是"匿名用户" → 被 `anyRequest().authenticated()` 拦 → 但此时**响应头已经发出去了**（SSE 已经开始推）→ 状态码写不进去 → "response is already committed"。

**修复**（SecurityConfig 里一行）：
```java
.securityContext(ctx -> ctx.requireExplicitSave(false))
```
让 SecurityContext 在异步派发时也能取到，问题消失。

**再遇到怎么查**：看到 `AuthorizationDeniedException` + `response is already committed` 这种"矛盾组合"（明明已认证却被拒 + 响应已提交），第一反应查**异步/过滤器**，而不是查密码。关键词：`requireExplicitSave`、async dispatch。

## 坑 3：没有全局 JAVA_HOME，编译运行报错

**症状**：`./mvnw` 报找不到 Java / JAVA_HOME 未设置。

**原因**：本机 JDK 装在 `D:\jdk17`，但没配全局 `JAVA_HOME`。每个新终端都丢失环境变量。

**修复**：**每次**打开新终端先执行：
```bash
export JAVA_HOME="D:/jdk17"
```
然后 `./mvnw spring-boot:run`。

**再遇到怎么查**：报错信息里出现 JAVA_HOME 字样，先 `echo $JAVA_HOME` 看有没有，没有就 export。

## 坑 4：Jackson 是第 3 代，包名全变了

**症状**：import 报红，找不到 `com.fasterxml.jackson.databind.ObjectMapper`。

**原因**：Spring Boot 4.x 内置的是 **Jackson 3**，包名从 `com.fasterxml.jackson` 变成了 **`tools.jackson`**：
```java
import tools.jackson.databind.ObjectMapper;
import tools.jackson.core.JacksonException;
```

**注意**：方法名 `readTree`、`asText` 这些用法没变，**只有包名变**。如果网上教程都是老包名，复制过来必报红——改成 `tools.jackson` 就通了。

## 坑 5：重试叠加成双重重试

**症状**：网络抖动时，一个请求重试了远超预期次数。

**原因**：Spring AI 自己带一层重试（`spring.ai.retry.max-attempts`），`ChatResilienceService` 又手动写了一层重试。两层叠加 = **最多 3×3 = 9 次**请求。

**修复**：在 `application.properties` 关掉 Spring AI 自带的：
```properties
spring.ai.retry.max-attempts=1
```
**重试逻辑只留一处**，行为可预测。

## 坑 6：Docker 里跑 PostgreSQL，psql 不在本机 PATH

**症状**：想 `psql` 查库，提示命令不存在。

**原因**：数据库跑在 Docker 容器 `ai-postgres`（pgvector:pg16）里，本机没有 psql。

**修复**：绕进容器执行：
```bash
docker exec -it ai-postgres psql -U postgres -d ai_chat
```

**再遇到怎么查**：报"命令不存在"先想想——这东西是不是在容器里？`docker ps` 看看有没有对应容器，有就 `docker exec` 进去。

## 坑 7：`@RequestParam` 的 GET 请求，前端必须 encode

**症状**：新建会话请求偶尔失败。

**原因/修复**：URL 里带中文（`?title=新对话`）没编码会出问题，前端用了 `encodeURIComponent('新对话')`。**URL 传参中文必编码。**

## 坑 8：删除按钮误触"切换会话"

**症状**：点会话行的 ✕，结果会话被切换了。

**原因**：删除按钮嵌在会话项 `<li>` 里，点击事件冒泡到父级 `li` 的 click 监听（切换会话）。

**修复**：删除按钮的 click 里 `e.stopPropagation()` 阻断冒泡。**嵌套可点击元素，记得 stopPropagation。**

## 坑 9：前端 localStorage 残留失效 sessionId

**症状**：刷新页面后报错 / 显示异常状态。

**原因**：`sessionId` 存在 localStorage，但该会话已被删除（或不是当前用户）——后端返回 404/403，前端没处理 `!resp.ok`。

**修复**：`loadHistory` 里 `if (!resp.ok)` 就把 `currentSessionId` 清空、提示"该会话不可用"。

## 排查方法论总结

| 遇到 | 先查 |
|---|---|
| 登录失败 | 查库看 password 是不是 `$2a$10$` 哈希 |
| 流式网络错误 | 看日志有没有 `AuthorizationDeniedException` + `response is already committed` |
| 编译报错 | `echo $JAVA_HOME`；看包名是不是 `tools.jackson` |
| 请求次数异常多 | 查有没有双重重试 |
| 命令找不到 | 想这东西是不是在容器/虚拟机里 |
| 点击行为不对 | 想事件冒泡（stopPropagation） |
