# 01 · 启动与配置

覆盖：启动入口、`application.yml`、`application.properties`、`HttpConfig`、`WebClientConfig`。核心问题是「配置分开在两个文件里，各管什么」。

## DemoApplication —— 启动入口

```java
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

一个注解搞定三件事：`@ComponentScan`（扫包找 @Service/@Controller/…）、`@Configuration`（加载 config 包）、`@EnableAutoConfiguration`（按 classpath 依赖自动装配）。**这就是"约定优于配置"**——我们什么都没配，Spring 靠包结构 + 依赖猜出这是 Web 应用、要连数据库。

## application.yml —— 数据库 / MyBatis / JWT

```yaml
spring:
  datasource:
    url: ${DB_URL:jdbc:postgresql://localhost:5432/ai_chat}
    username: ${DB_USERNAME:postgres}
    password: ${DB_PASSWORD:123456}
    driver-class-name: org.postgresql.Driver
mybatis:
  mapper-locations: classpath:mapper/*.xml
jwt:
  secret: ${JWT_SECRET:my-super-secret-key-for-ai-chatbot-project-2026}
  expiration: ${JWT_EXPIRATION:86400000}
```

三个要点：

1. **`${变量:默认值}`** 语法 = 环境变量优先，没设就用冒号后面的兜底。演示环境直接连本地库，生产只要设 `DB_PASSWORD`、`JWT_SECRET` 就覆盖掉明文。
2. **JWT 密钥必须 ≥ 32 字符**：`JwtService` 用 `Keys.hmacShaKeyFor()` 构造 HMAC-SHA 密钥，太短会抛异常。默认值故意留了 32+ 字符。
3. **`expiration: 86400000`** = 24 小时的毫秒数。token 过期后 `extractClaims` 抛异常 → 过滤器不设认证 → 401。

## application.properties —— Spring AI 专属

```properties
spring.ai.deepseek.api-key=${DEEPSEEK_API_KEY}
spring.ai.deepseek.chat.options.model=deepseek-v4-flash

spring.ai.retry.max-attempts=1
```

- **模型**：`deepseek-v4-flash` 是推理模型，输出会先有思考过程再出正文——前端那两个气泡就是为它设计的。
- **`spring.ai.retry.max-attempts=1` 是刻意的**：Spring AI 自带重试默认 10 次，而我们自己在 `ChatResilienceService` 里手动重试。不关掉就会**重试 × 重试 = 双重试**（第一次失败被手动重试，底层再帮你重试 10 次）。详见 [[05-Chat核心-流式与重试]]。

## HttpConfig —— 阻塞式 HTTP（给工具用）

```java
@Bean
public RestClient.Builder restClientBuilder() {
    SimpleClientHttpRequestFactory factory = new SimpleClientHttpRequestFactory();
    factory.setConnectTimeout(5000);    // 连接超时 5s
    factory.setReadTimeout(60_000);     // 读取超时 60s
    return RestClient.builder().requestFactory(factory);
}
```

只有一个 `RestClient.Builder` Bean。它是**阻塞式**的（同步等结果）。谁在用？`WeatherTools`——天气工具要等 HTTP 响应，同步调用简单直接。见 [[09-函数调用与工具]]。

## WebClientConfig —— 流式 HTTP（给 DeepSeek 用）

```java
HttpClient httpClient = HttpClient.create()
        .option(ChannelOption.CONNECT_TIMEOUT_MILLIS, 5_000)
        .doOnConnected(connection -> connection.addHandlerLast(
                new ReadTimeoutHandler(60, TimeUnit.SECONDS)));

return WebClient.builder()
        .clientConnector(new ReactorClientHttpConnector(httpClient));
```

**为什么有两个 HTTP 客户端？** 这是这个项目最容易困惑的地方之一：

- `HttpConfig` 的 `RestClient` → **同步**请求，给工具调用。
- `WebClientConfig` 的 `WebClient` → **异步 + 流式**，Spring AI 的 `ChatClient.stream()` 底层就是 WebClient/Reactor Netty，`RestClient` 完全用不上它。

所以流式调 DeepSeek 的超时要在这单独配。两个超时含义不同：

| 超时 | 含义 |
|---|---|
| 连接超时 5s | 建立 TCP 连接超过 5s 失败 |
| **读取空闲**超时 60s | 连接建立后**连续 60s 收不到任何数据**才断。注意是"空闲"，长文本流式输出 2 分钟也不会被误杀 |

## 环境变量的完整清单

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DB_URL` | jdbc:postgresql://localhost:5432/ai_chat | 数据库连接 |
| `DB_USERNAME` | postgres | 数据库用户 |
| `DB_PASSWORD` | 123456 | 数据库密码 |
| `JWT_SECRET` | my-super-secret-... | JWT 签名密钥 |
| `JWT_EXPIRATION` | 86400000 | 过期毫秒数 |
| `DEEPSEEK_API_KEY` | （无） | DeepSeek 密钥，**必须设** |
