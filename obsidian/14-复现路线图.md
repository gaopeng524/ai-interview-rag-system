# 14 · 复现路线图（照着 interview-guide 自己搭）

> 目标：**不抄代码，按 [[13-interview-guide框架蓝图]] 的结构，在你的 demo 项目基础上逐步复现**，每一步自己动手、我当把关人。
> 原则：每个阶段都有"验收标准"（跑通一个可演示的闭环），做完一个再看下一个，不贪多。

## 阶段 0 · 现状盘点（已完成）

你现有的 demo 项目 = interview-guide 的"最小骨架"：注册/登录（JWT）、会话管理、SSE 流式（reasoning/content 信封）、双层记忆、函数调用。

**对照缺口**（每个缺口就是一个阶段）：

| # | 缺口 | 对应 interview-guide | 学到的新概念 |
|---|---|---|---|
| 1 | 无统一响应/错误码规范 | common/result + exception | 生产代码规范 |
| 2 | 模型写死 DeepSeek | modules/llmprovider | 多 Provider 抽象 |
| 3 | **无知识库/RAG** | **modules/knowledgebase** | **Embedding/向量检索** |
| 4 | 无异步任务 | common/async | 消息队列/重试 |
| 5 | 无结构化输出/评估 | common/evaluation | 结构化输出 |

## 阶段 1 · 统一规范层（1~2 天）

**动手做**（改造现有 demo）：
1. 加 `Result<T>` 统一响应，所有 Controller 返回它。
2. `BusinessException` 升级：加 `ErrorCode` 枚举（如 `USER_NOT_FOUND`、`UNAUTHORIZED`）。
3. 全局异常处理器改成"HTTP 200 + Result.error(code, message)"（interview-guide 风格）。
4. 配置收敛：散落的 `@Value` 收进 `@ConfigurationProperties` 类。

**对应原项目**：`common/result/Result.java`、`common/exception/`、`common/config/`

**验收**：所有接口返回统一格式 `{code, message, data}`；`mvnw test` 通过。

## 阶段 2 · 多 Provider 抽象（2~3 天）

**动手做**：
1. 写 `LlmProviderRegistry`：按配置动态创建 `ChatClient`（DeepSeek 作为第一个，留出接口）。
2. 把 `ChatResilienceService` 里写死的 ChatClient 改成从 registry 取。
3. （进阶）provider 表落库 + API key AES 加密存储。

**对应原项目**：`modules/llmprovider/`、`common/ai/LlmProviderRegistry.java`

**新概念**：`ChatClient.Builder` 动态构建、OpenAI 兼容协议（DeepSeek/千问/Kimi 一套代码）

**验收**：改配置就能切换模型，聊天照常工作。

## 阶段 3 · RAG 最小知识库 ★核心（3~5 天）

这是 interview-guide 最值钱的部分，也是当初定下的方向。**pgvector 容器你已有**。

**动手做**（最小闭环）：
1. `EmbeddingConfig`：配好 embedding 模型 + pgvector `VectorStore`。
2. 上传接口：接收 txt（先用纯文本，`/api/kb` 上传）。
3. 解析 + 分块：`TokenTextSplitter`（~800 tokens）。
4. 向量化入库：`vectorStore.add()`（注意批量 ≤10）。
5. 问答接口：检索 `similaritySearch()` → 拼 Prompt → SSE 流式返回。
6. 前端：加一个"知识库问答"入口（复用现有 SSE 解析）。

**对应原项目**：`modules/knowledgebase/`（重点看 `KnowledgeBaseVectorService`、`KnowledgeBaseQueryService`、`RagChatController`）

**新概念**：Embedding、向量相似度、topK/minScore、查询改写、RAG 完整链路

**验收**：上传一篇文档 → 问它文档里的问题 → 能引用内容答对，而不是瞎编。

## 阶段 4 · 异步任务化（2~3 天）

**动手做**：
1. Docker 起 Redis（`docker run -d -p 6379:6379 redis`）。
2. 实现 `AbstractStreamProducer` / `AbstractStreamConsumer` 模板。
3. 把阶段 3 的"分块+向量化"移进异步队列，上传接口立刻返回。
4. 加失败重试 + 恢复调度器。

**对应原项目**：`common/async/`、`knowledgebase/listener/`（`VectorizeStreamProducer/Consumer`、`QuestionGenerationRecoveryScheduler`）

**新概念**：Redis Stream、生产者/消费者模式、ACK、失败补偿调度

**验收**：上传大文件秒回，后台异步向量化，完成后能检索到。

## 阶段 5 · 深化（可选，按兴趣挑）

- **结构化输出 + 评估引擎**：面试/问答后让模型按固定 JSON 出分（`common/evaluation`）。
- **Skill 驱动出题**：用 `SKILL.md` 定义出题范围（`modules/interview/skill/`）。
- **Tika 多格式解析**：PDF/DOCX 上传（`infrastructure/`）。
- **简历分析**：完整复刻 resume 模块。

## 关键提醒（复现时别踩坑）

1. **保留 MyBatis**：interview-guide 用 JPA，但持久层技术不影响框架复现，别重写你的 Mapper。
2. **JDK 17 够用**：interview-guide 要 Java 25（虚拟线程），我们复现用 17 完全没问题——虚拟线程不是核心概念。
3. **embedding 模型**：DeepSeek 官方没有 embedding，需要配一个支持 OpenAI 兼容 embedding 的（如 dashscope text-embedding / 其他兼容服务）。这是阶段 3 的第一个技术点。
4. **先跑通再优化**：RAG 先做"上传就能问"的最小闭环，两阶段提交/查询改写/过滤那些生产细节等闭环跑通再逐步加。
5. **每个阶段做完都在原项目 clone 里对照一遍**：`D:\javacode\interview-guide-ref\app\src\main\java\interview\guide\modules\knowledgebase\` 等，看自己写的和它的差异。

## 建议节奏

```
阶段 1（规范层）→ 阶段 2（多 Provider）→ 阶段 3（RAG ★）→ 阶段 4（异步）→ 阶段 5（深化）
   1~2天            2~3天              3~5天          2~3天          按兴趣
```

> 阶段 1/2 是为阶段 3 铺路（统一规范 + 模型抽象），可以直接做；如果心急想先看 RAG 效果，阶段 3 也允许单独提前做，但建议至少把 `Result<T>` 和异常规范带上。
