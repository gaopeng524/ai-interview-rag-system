# 10 · 前端（index.html）

一个文件、无框架的原生 HTML + JS。它不是"随便写写的页面"，而是整个 SSE 流式交互的关键一环。覆盖：登录/注册、会话侧边栏、**fetch 手动解析 SSE**。

## 一、整体结构

```
静态页（src/main/resources/static/index.html）
  ├─ 登录/注册视图（#authView）      → 未登录时显示
  ├─ 会话视图（#chatView）           → 登录后显示
  │    ├─ 左侧边栏（#sidebar）       → 会话历史列表，可切换/删除
  │    └─ 右侧聊天区（#chat）        → 消息气泡 + 输入框
  └─ <script>：全部前端逻辑
```

Spring Boot 会把 `resources/static/` 下的文件当静态资源直接伺服，访问 `http://localhost:8080/` 就是它。无需任何构建工具，改完刷新就能看。

## 二、为什么不用 EventSource，要用 fetch 手动解析

这是全前端最重要的一个决策。SSE 标准里有个 `EventSource` 对象，但它有**两个致命限制**：

1. **只能用 GET** —— 我们的流式接口是 `POST /chat/sessions/{id}/messages`。
2. **不能带自定义请求头** —— 我们的接口要 `Authorization: Bearer <token>`（JWT 认证）。

```js
// EventSource 做不到的两件事：
// 1. EventSource 只支持 GET
// 2. EventSource 无法设置 Authorization 头
```

所以退而求其次用 `fetch` + `ReadableStream` 手动解析。代价是代码多一点，但换来"POST + 认证头 + 流式"三者兼得。**这是流式 AI 前端的标准套路**。

## 三、登录 / 注册

```js
if (authMode === 'login') {
    resp = await fetch('/users/login', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ username, password })
    });
    token = await resp.text();          // 登录直接返回 JWT 字符串
} else {
    // 注册
    resp = await fetch('/users', { ... });
    // 注册成功后自动登录（再调一次 /users/login）
}
localStorage.setItem('token', token);
showChatView();
```

几个设计点：
- **登录返回的是 JWT 字符串本身**（`resp.text()`，不是 JSON），后端 `UserController.login` 返回 `String`。
- **注册后自动登录**：注册成功再调一次登录接口，无缝进入。用户体验顺滑。
- token 存 `localStorage`：浏览器刷新不丢，下次打开直接进会话视图（`if (token) showChatView()`）。
- `toggleAuth()` 在登录/注册之间切换标题和按钮文案，同一套输入框复用。

## 四、通用请求封装 —— 自动带 token、自动处理 401

```js
async function api(url, options = {}) {
    const resp = await fetch(url, {
        ...options,
        headers: { 'Authorization': 'Bearer ' + token, ...(options.headers || {}) }
    });
    if (resp.status === 401) {
        alert('登录已过期，请重新登录');
        localStorage.removeItem('token');
        localStorage.removeItem('sessionId');
        location.reload();
        throw new Error('unauthorized');
    }
    return resp;
}
```

**所有**带认证的请求都走这个 `api()`：
- 自动加 `Authorization: Bearer <token>` 头——你永远不用手动拼。
- **401 统一处理**：token 过期/无效 → 提示重新登录 → 清掉 localStorage → 刷新回登录页。不用每个请求都写一遍。

`throw new Error('unauthorized')` 是为了让调用方（如 `sendMessage` 的 catch）能识别"这是认证失败，不是普通网络错误"，避免再弹一个误导性的错误气泡。

## 五、会话侧边栏 —— 增删查切换

```js
async function loadSessions() {
    const resp = await api('/chat/sessions');
    const sessions = await resp.json();
    renderSessionList(sessions);
}
```

### 渲染列表 + 每行的删除按钮

```js
for (const s of sessions) {
    const li = document.createElement('li');
    li.className = 'session-item' + (s.id === currentSessionId ? ' active' : '');
    li.addEventListener('click', () => selectSession(s.id));   // 点击切换

    const del = document.createElement('button');
    del.className = 'session-del';
    del.textContent = '✕';
    del.addEventListener('click', (e) => {
        e.stopPropagation();       // ⚠️ 阻止事件冒泡，否则会误触"切换会话"
        deleteSession(s.id);
    });
    ...
}
```

**`e.stopPropagation()` 是新手最容易漏的坑**：删除按钮嵌在会话项里，点击删除时事件会冒泡到父级触发"切换会话"。stopPropagation 把它拦在删除按钮这一层。

### 切换会话

```js
async function selectSession(id) {
    if (id === currentSessionId) return;   // 同一个会话，忽略
    currentSessionId = id;
    localStorage.setItem('sessionId', id);
    await loadHistory();      // 加载这个会话的历史消息
    loadSessions();           // 刷新列表，让高亮移动到当前项
}
```

### 新建会话

```js
const resp = await api('/chat/sessions?title=' + encodeURIComponent('新对话'), { method: 'POST' });
const session = await resp.json();
currentSessionId = session.id;
```

创建时用 `@RequestParam String title` 传标题（这里给默认值"新对话"），返回的 JSON 里有自增 id（MyBatis `useGeneratedKeys` 回填，见 [[07-数据访问层]]）。

## 六、历史消息加载

```js
async function loadHistory() {
    const resp = await api('/chat/sessions/' + currentSessionId + '/messages');
    if (!resp.ok) {
        // localStorage 里的 sessionId 已失效（被删了/不是你的）
        currentSessionId = null;
        localStorage.removeItem('sessionId');
        ...
    }
    const messages = await resp.json();
    chatBox.replaceChildren();          // 先清空
    for (const m of messages) {
        appendBubble(m.role === 'user' ? 'user' : 'ai', m.content);
    }
}
```

注意**对 401 之外的 !ok 也有处理**：比如 `sessionId` 还残留在 localStorage 但会话已删——此时后端返回 404/403，前端把状态清掉提示"该会话不可用"。这个分支是实际调试时发现的坑（见 [[12-坑与排查]]）。

## 七、核心：fetch 流式读 SSE

这是全文件最核心的一段：

```js
const resp = await api('/chat/sessions/' + currentSessionId + '/messages', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ content: text })
});
if (!resp.ok || !resp.body) throw new Error('请求失败');

const reader = resp.body.getReader();       // ReadableStream 的读取器
const decoder = new TextDecoder();
let buffer = '';

while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });

    // SSE 协议：事件之间用空行（\n\n）分隔，每条事件里是 data: {...}
    let idx;
    while ((idx = buffer.indexOf('\n\n')) !== -1) {
        const raw = buffer.slice(0, idx);
        buffer = buffer.slice(idx + 2);
        const dataLine = raw.split('\n').find(l => l.startsWith('data:'));
        if (!dataLine) continue;
        handleEnvelope(JSON.parse(dataLine.slice(5).trim()), aiMsg);
    }
}
```

逐行拆解：

| 代码 | 作用 |
|---|---|
| `resp.body.getReader()` | 拿到响应体的流读取器。`await reader.read()` 每次返回一段二进制块（**chunk**） |
| `decoder.decode(value, {stream:true})` | 二进制→字符串。`stream:true` 表示"数据可能被截断在中间"，正确处理多字节中文 |
| `buffer += ...` | 攒进缓冲区，因为**一次 chunk 里可能包含多个事件** |
| `buffer.indexOf('\n\n')` | SSE 协议的分隔符：事件之间用空行分隔 |
| `while` 内层循环 | **把缓冲区里所有完整事件全部处理完**，剩下半截留到下一个 chunk 再拼 |
| `raw.split('\n').find(...)` | 找 `data:` 开头的那行，就是我们要的 JSON |
| `dataLine.slice(5)` | 去掉 `data:` 前缀（5 个字符） |

**为什么 buffer + while 循环这么绕**：网络把数据切成块返回，一个事件可能被切成两半（尤其中文多字节），多个事件也可能挤在一个块里。缓冲区 + 循环"切一个处理一个"就是处理这种边界情况的通用解法。

## 八、handleEnvelope —— 按 type 分流渲染

后端吐的是 JSON 信封：`{"type":"reasoning"|"content"|"error","text":...}`（见 [[05-Chat核心-流式与重试]]）。

```js
function handleEnvelope(env, st) {
    if (env.type === 'reasoning') {
        // 首次出现时创建"思考过程"折叠块
        if (!st.thinkBlock) {
            st.thinkBlock = document.createElement('div');
            st.thinkBlock.className = 'msg reasoning';
            ...  // 💭 思考过程，可点击折叠/展开
        }
        st.thinkBody.textContent += env.text;   // 逐段追加
        status.innerHTML = '💭 思考中…（' + (++st.thinkCount) + ' 段）';
    } else if (env.type === 'content') {
        st.textSpan.textContent += env.text;    // 正文逐字追加
        status.innerHTML = '<span class="live">生成中…</span>';
    } else if (env.type === 'error') {
        appendBubble('error', '⚠ ' + env.text); // 红色错误气泡
        status.textContent = env.text;
    }
}
```

- **`st`（stream state）**：`appendStreamBubble()` 返回的引用集合，保存 AI 气泡 DOM、思考块、计数器。**用 `+=` 追加**——每来一个分片拼一段，这就是"流式打字机"效果。
- **思考折叠块**：首次 reasoning 才创建；点头部可折叠/展开（`st.collapsed` 切换 `display`）。
- 状态栏实时变化：`思考中…（N 段）` → `生成中…` → `接收完成`。

## 九、防并发 —— setBusy

```js
function setBusy(busy) {
    sendBtn.disabled = busy;
    newConvBtn.disabled = busy;
    delConvBtn.disabled = busy;
}
```

流式进行中禁用发送/新建/删除三个按钮，防止用户连续点发送并发起多个流。

## 十、前端数据流总览

```
浏览器 localStorage                后端
  token ────────────────────────→ Authorization: Bearer
  sessionId ────────────────────→ /chat/sessions/{id}/messages
                                     │
    SSE 事件流 ◄──────────────────────┘
  handleEnvelope(type)
    reasoning → 折叠思考块
    content   → 正文追加
    error     → 红色气泡
```
